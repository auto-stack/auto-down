plan-022 (lang-682 batch, D17): external doc replacement no longer swallows keystrokes. Root cause (jade-edit PLAN-002 probe evidence): `replaceDoc` kept cached per-block controllers alive while deterministic block ids (`block-N`) collide across documents — a stale controller's `knownText` baseline pointed at the old doc, so `diffToOp` produced ops that landed misaligned or no-op'd, and the unconditional `knownText = newText` advance desynced it from the model permanently (every later keystroke reached the DOM but not the model until a blur-flush reconcile). Fixes: ① `EngineEditor` bumps a `docEpoch` and clears the `hosts` map in the replaceDoc watch — host vnodes remount (key includes docEpoch) and fresh controllers seed from the new doc; ② `BlockHostController.onInput` advances `knownText` only when the op mutated the tree (`engine.doc` reference check) and resyncs from the model on a silent no-op instead of poisoning the diff baseline; ③ `onEnter` clears the baseline only when the split actually landed (`findBlock(newId)`). Regression tests: `src/editor/__tests__/d17-input-pipeline.test.ts` (3 cases: no-op realign, per-stroke emission after replaceDoc, failed-split non-poisoning). Known residual (follow-up): a composition session interrupted by host unmount leaves `composing` latched on a surviving controller — unreachable via replaceDoc after ①, needs an unmount-compositionCancel seam. jade-edit e2e keeps its neutral-blur flush adaptation until this ships in a release and the downstream re-verification retires it (669 receipt pattern).
